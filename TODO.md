# About

Часть участков распределена и изменения в ней проводятся по запросу к владельцу участка. Для агентов изменять что-либо из участков определенных участников нельзя. Какие именно участки кому принадлежат смотри в `/.github/CODEOWNERS`

### ALL

+ Реализовать класс `InputMap`
    > Тип сейчас не реализован, как и сам класс. Подразумевается логика в которой `InputMap` срабатывает по `keycode` только для конкретного биндинга толкьо если есть определенный контекст. То есть, имеется ввиду что если сейчас стоит контекст `gui`, то биндинги для управления персонажем работать не будут. Пользователь делает `inputmap:get_context(enumitem_context_bind) : event<enumitem_context>`, получает ивент и спокойно работает с этим. Класс сам переключается между тем чем надо. Почему класс? Чтобы сервисов поменьше было. Требует доработки, потому что нужно как-то определять что к чему.

    + Реализовать енамы контекста для класса
        > Подразумевается, что в зависимости от контекста будут активироваться определенные биндинги. Это как сами `enumobject`, так и `enumitem` внутри них. Также реализовать это в `core.d.luau`.
        + Контекст gui
        + Контекст human
        + Контекст machine
        + Контекст airmachine

    + Реализовать класс `InputBinder`
        > У класса есть свойство которое определяет его контекст. `InputMap` пользуется этим полем и через функцию `inputbinder:get_binding_keycode_to(enumitem_context_bind) : Enum.Keycode` получает ключ и проверяет то это или не то.
